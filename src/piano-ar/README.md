# 🎹 Piano AR — Keymento 통합 진입점

웹캠으로 피아노 건반 평면을 잡아 그 위에 AR 오버레이를 그리고,
같은 프로세스에서 웹 UI와 연주 판정 세션을 함께 돌린다.

```
메인 스레드       카메라 → ArUco 보정 → 원근 변환 → 건반 오버레이 → HUD
백그라운드 스레드  웹 UI 서버(:8321) + 판정 세션(src/perform/session.py)
```

OpenCV 의 창·키 입력은 메인 스레드에서만 안정적이라, 세션은 상태만
갱신하고 그리기는 전부 `main.py` 의 루프가 맡는다.

---

## ▶️ 실행

프로젝트 루트의 `run.bat` 을 쓴다. venv·인코딩·MIDI 포트를 알아서 잡는다.

```powershell
.\run                 전체 — 카메라 + 건반
.\run demo            건반 없이 — 정답지를 자동 연주 (카메라는 사용)
.\run test            카메라도 건반도 없이 — 웹 UI + 판정만 (가장 빠름)
.\run base            AR 기준음 잡기 ★ 새 건반이면 처음 한 번
.\run ports           연결된 MIDI 입력 포트 목록
.\run help            한글 안내
```

`.\run` 하면:

1. 카메라가 열리고 캘리브레이션 화면이 뜬다 (저장된 좌표가 있으면 건너뜀).
2. AR 창이 열리고 **브라우저가 자동으로 열린다**.
3. 브라우저에서 **곡·모드·속도**를 고르고 시작.
4. AR 창이 세션 상태를 따라간다.

MIDI 포트는 기본 `auto` 가 가상 포트(loopMIDI 등)를 빼고 진짜 건반을
찾으므로 보통 지정할 필요가 없다. 안 잡힐 때만 직접 고른다:

```powershell
.\run --midi-port 2
.\run --midi-port keystation      # 이름 조각으로도 됨
```

런처 없이 직접 실행해도 된다:

```powershell
venv\Scripts\python.exe src\piano-ar\main.py --demo --no-camera
```

### 옵션

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--midi-port X` | `auto` | 번호(`2`) 또는 이름 조각(`keystation`). `auto` 는 가상 포트를 빼고 진짜 건반을 찾는다 |
| `--demo` | — | 건반 없이 — 정답지를 자동 연주 |
| `--demo-wrong N` | `7` | 데모에서 N 번째마다 일부러 틀리기 (0 이면 전부 정확히) |
| `--no-camera` | — | 카메라·AR 창 없이 웹 UI 와 판정만 |
| `--no-browser` | — | 브라우저 자동 열기 끄기 |
| `--udp-port N` | `9998` | 라즈베리파이(hw/pi_midi) UDP 수신 포트 |
| `--port N` | `8321` | 웹 UI HTTP 포트 |
| `--host ADDR` | `0.0.0.0` | 웹 UI 바인딩 주소 |
| `--camera N` | `0` | 카메라 장치 번호 |
| `--countdown N` | `5` | 시작 전 카운트다운(초) |
| `--speed-scale F` | `0.35` | 설정 속도에 곱하는 배율 (아래 참고) |
| `--song PATH` | — | `--no-serve` 자유 재생에 쓸 MIDI 파일 |
| `--no-sound` | — | 건반 소리 에코 끄기 |
| `--no-serve` | — | 웹 UI·세션 없이 악보만 흘려보기 |
| `--list-midi` | — | MIDI 입력 포트 목록만 출력 |

### 창 안에서 쓰는 키

| 키 | 동작 |
|---|---|
| `V` | 보기 전환: 원본 카메라 화면(기본) ↔ 건반만 잘라 편 화면 |
| `F` | 카메라 화면 180° 회전 (연주자 맞은편 카메라용, 설정에 저장) |
| `C` | 카메라 0/1 전환 (전환 후 다시 보정) |
| `M` | 수동 캘리브레이션 (건반 네 모서리 클릭, 마커가 다 보이면 ArUco 가 이 모서리를 따라감) |
| `A` | ArUco 자동 보정 켜기/끄기 |
| `R` | 지금 보이는 ArUco 위치로 보정 초기화 |
| `P` | 세션 다시 시작 (`--no-serve` 에서는 악보 재생만) |
| `ESC` | 종료 |

## 🎯 두 가지 모드

브라우저에서 고른다. 화면 표시가 모드마다 다르다.

| | 연습 | 일반 |
|---|---|---|
| 진행 | 정답을 칠 때까지 같은 음에 머무름 | 악보 시계대로 흐름, 늦으면 Miss |
| AR 표시 | 눌러야 할 건반이 **호박색으로 맥동** | 목표 시각에 맞춰 색이 바뀌는 타이밍 마커 |
| 박자 | 판정 안 함 | ±300/600/900ms → Perfect/Great/Good |
| 점수 | 음정만 (한 번에 맞춘 비율) | (음정 + 박자) / 2 |

일반 모드의 타이밍 마커는 판정 창과 같은 경계로 색이 바뀐다(모두 실제
시간 기준, 속도 배율이 반영된다).

| 목표 시각 기준 | 표시 | 지금 치면 |
|---|---|---|
| 1.5초 전 ~ 0.9초 전 | 하늘색 점 + 줄어드는 링 | 판정 안 됨(오타) |
| ±0.9초 안 | 노랑 | Great / Good |
| ±0.3초 안 | **초록** (링이 점에 닿는 순간이 정확한 타이밍) | Perfect |
| 0.9초 뒤 | 사라짐 | Miss |

친 음은 곧바로 지워지고 등급 색으로 잠깐 번쩍인다. 같은 건반에 음이
이어 나오면 앞 음이 끝날 때까지 앞 음만 그린다.

화음은 같은 시각(20ms 이내)의 음을 한 덩어리로 묶어 **순서를 따지지
않는다**. 연습 모드에서는 아직 안 친 음만 계속 빛나고, 첫 음을 누른 뒤
**0.3초 안에 모든 음을 눌러야** 통과한다. 일부만 치고 시간이 지나거나
그사이 틀린 음을 섞으면 화음 전체가 다시 빛나고 HUD 에
`Chord: missing G4` 처럼 빠진 음이 뜬다 — 남은 음만 나중에 따로 쳐서는
넘어가지 않는다.

## ⏩ 속도 배율 (`--speed-scale`)

악보가 눈으로 따라갈 수 있을 만큼 느려야 해서, 웹 UI 에서 고른 속도에
`0.35` 를 한 번 더 곱해 세션에 넘긴다. 판정 목표 간격도 같은 값으로
늘어나므로 화면과 채점이 어긋나지 않는다.

원래 속도로 돌리려면 `--speed-scale 1` 을 준다. 현재 유효 속도는 콘솔과
웹 UI 속도 카드에 함께 표시된다.

## 🖥️ 화면 구성

기본은 **원본 카메라 화면을 자르지 않고** 보여 준다. 캘리브레이션
결과를 역원근 변환으로 그 위에 투영한다.

- 노란 사각형 + 건반 격자: 실제로 적용 중인 캘리브레이션
- 자홍 점: 이번 프레임에서 찾은 ArUco 마커 중심(ID 0·1·2·3). 넷이 다
  안 잡혀도 잡힌 것만 찍힌다.

마커는 한 프레임에 넷이 함께 잡히지 않아도 된다. 0.5초 안에 본 마커는
마지막 위치를 쓰고, 하나만 비면(손이 가린 경우 등) 나머지 셋이 움직인
만큼 적용 중인 보정의 네 번째 점을 옮겨 채운다(`ID n est.`). 모자라면
HUD 우측에 `ArUco 2/4 - missing ID 1,3` 처럼 빠진 ID 가 뜬다.

### 마커 ↔ 건반 모서리

마커는 건반 위·아래 패널에 붙으므로 마커 중심은 건반 모서리가 아니다.
그대로 쓰면 격자가 옆으로 늘어나고 기울어 건반과 조금씩 어긋난다.
그래서 **처음 한 번, 마커 4개가 다 보이는 상태에서 `M` 으로 건반 네
모서리를 찍는다.** 그 순간 모서리가 마커 사각형 안 어디에 있는지가
`calibration/key_area.json` 에 저장되고, 그 뒤로 ArUco 자동 보정은 마커가
아니라 이 모서리를 따라간다(노란 사각형이 자홍 점이 아닌 건반 끝에 붙는다).
마커와 건반 사이의 관계만 담으므로 카메라를 바꾸거나 `F` 로 돌려도
다시 찍을 필요가 없고, 마커를 옮겨 붙였을 때만 다시 `M` 을 누르면 된다.
이 파일이 없으면 예전처럼 마커 중심을 모서리로 쓴다.

자동 보정이 좌표를 옮기면 노란 사각형이 따라 움직이는 게 그대로
보인다. 음표 마커는 `800x200` 워프 공간에서 그린 뒤 칠해진
픽셀만 원본 화면으로 되돌려 붙인다. `V` 를 누르면 예전처럼 건반만
잘라 편 화면으로 바뀐다.

어느 보기든 글자는 화면 위에 얹지 않고, 아래에 **HUD 띠**를 따로 붙여
거기에 그린다. 건반 영역은 오버레이 전용으로 비워 둔다.

HUD 에는 모드·곡, 다음 목표 음, 진행률, 결과가 뜨고, ArUco 상태는
오른쪽 끝에 붙는다. 카운트다운 숫자와 최종 점수만은 멀리서도 보이도록
건반 영역 한가운데에 크게 띄운다.

한글은 그리지 않는다 — `cv2.putText` 는 Hershey 벡터 폰트만 그릴 수
있어 ASCII 밖은 `?` 로 깨진다. 음이름은 `judgement.note_to_ascii`
(60 → `C4`)로 다시 만들어 쓴다.

## 🎯 기준음 (중요)

AR 은 워프된 화면의 **맨 왼쪽 흰건반이 내는 MIDI 번호**를 알아야 마커를
제 위치에 그린다. 이 값이 실제 건반과 어긋나면 마커가 통째로 옥타브
단위로 밀린다 — 짚어 준 건반을 눌러도 판정이 안 맞고, 연습 모드는 그
자리에서 영영 기다린다. 화음은 두 음이 다 맞아야 해서 특히 "화음만
인식이 안 되는 것처럼" 보인다.

새 건반을 물렸다면 처음 한 번만 맞추면 된다:

```powershell
.\run base       # 맨 왼쪽 키를 한 번 누르면 저장된다
```

받은 음은 그 이하 가장 가까운 도(C)로 내림하므로, 옆 키를 눌러도 같은
옥타브면 제대로 잡힌다. 숫자로 직접 줄 수도 있다(도여야 한다):

```powershell
.\run --base-note 60
```

값은 `data/settings.json` 의 `base_note` 에 저장된다. 실행할 때마다
현재 기준음과 표시 음역, 그리고 고른 곡이 그 안에 들어오는지 콘솔에
찍어 준다.

기본값은 **48 (C3)** 이다 — Keystation Mini 32 의 맨 왼쪽 키가 48 을
보내고, 흰 19 + 검은 13 = 32키가 C3~G5(48~79) 로 그 건반과 맞는다.

`songs/` 의 곡은 60(C4) 부터 시작하므로 **화면 왼쪽 한 옥타브에는 마커가
뜨지 않는다.** 기준음이 틀려서가 아니라 곡이 그 음역을 안 쓰기 때문이다.

## 📂 구조

```
piano-ar/
├── main.py                   # 통합 진입점 (AR 루프 + 웹 UI 스레드 + HUD)
├── camera/capture.py         # 웹캠 연결
├── calibration/calibrator.py # ArUco 자동 보정 + 4점 수동 보정
├── keyboard/
│   ├── layout.py             # 건반 구조 정의 (흰/검 패턴)
│   └── mapping.py            # 좌표 계산
├── ar/overlay.py             # 건반 위 마커 렌더 (시간축 / 목표 맥동)
└── utils/transform.py        # perspective transform (800x200)
```

바깥 모듈과의 연결:

- `src/gui/server.py` — `SessionManager` 를 공유하고 `create_server()` 로
  서버를 만들어 별도 스레드에서 돌린다.
- `src/perform/session.py` — `load_judgement_notes()` 로 오버레이용 노트를
  읽는다. 판정과 **같은 정답지**를 쓴다.
- `src/settings` — 곡·속도·입력 소스·연습 모드.

## 🎵 곡 고르기

기준음 48(C3) 기준, 건반 음역은 C3~G5. 곡이 쓰는 음역과 비교한다.

| 곡 | 음 수 | 화음 | 화음 최대 폭 | 길이 | 음역 | 건반 밖 |
|---|---|---|---|---|---|---|
| head-shoulder-knee-and-toe | 39 | 0곳 | — | 15초 | C4~D5 | 0 |
| happy-birthday-to-you-c-major | 28 | 3곳 | **19반음** | 11초 | C4~G5 | 0 |
| abc-song-in-c | 114 | 23곳 | 10반음 | 32초 | C4~B4 | 0 |
| twinkle-twinkle-little-star | 4473 | 894곳 | 28반음 | **11분 27초** | C4~F6 | **536음** |

twinkle 은 F6(89)까지 올라가는데 건반 최고음이 G5(79)라 **이 건반으로는
아예 칠 수 없다.** 나머지 세 곡은 전 음이 건반 안에 들어온다.

시연에는 `head-shoulder-knee-and-toe`(짧고 단음)를 쓴다. twinkle 은
변주 전체가 들어 있어 11분이 넘으므로 적합하지 않다.

**화음 폭에 주의한다.** happy-birthday 의 화음은 멜로디 + 베이스 구조라
도4 + 솔5 처럼 19반음 떨어져 있다. 32키 컨트롤러에서 한 손으로는 못
짚으므로, 화음 동작을 확인하려면 두 손으로 치거나 폭이 좁은
`abc-song-in-c`(10반음)를 쓴다.

## ⚠️ 주의

- 카메라는 고정해야 한다. 흔들리면 ArUco 자동 보정이 계속 재계산한다.
- 노트북 화면에 붙인 카메라처럼 연주자 맞은편에서 찍으면 건반이 거꾸로
  보인다(글자가 뒤집히고 낮은 음이 오른쪽). `F` 를 한 번 누르면 화면과
  보정 좌표가 함께 180° 돌아가고, `data/settings.json` 의
  `camera_rotate_180` 에 저장돼 다음 실행부터 그대로 쓴다. 마커 ID 는
  연주자 기준(0 왼쪽 위 → 시계 방향)으로 붙인다.
- 조명이 일정해야 마커 인식률이 높다.
- 마커는 화면에서 한 칸(4x4 + 테두리 = 6칸)이 세로로도 5px 이상은
  돼야 안정적으로 읽힌다. 카메라가 낮게 비스듬히 보면 세로가 납작해지니
  마커를 키우거나 카메라를 더 위에서 내려다보게 둔다. 흰 여백은 1칸
  이상 남긴다(검은 건반 몸체에 바로 붙으면 테두리가 묻힌다).
- 마커 위를 광택 테이프로 덮지 않는다. 반사 띠 하나만 지나가도 인식률이
  크게 떨어진다(합성 실험: 100% → 30% 안팎). 가장자리만 붙이거나
  무광 테이프·스티커 용지를 쓴다.
- 건반 전체와 마커 4개(ID 0·1·2·3)가 화면에 보여야 한다.
- 컨트롤러(Keystation 등)는 자체 음원이 없다. 소리는 세션 쪽
  소프트웨어 신디사이저(`src/midi/synth.py`)가 낸다.
